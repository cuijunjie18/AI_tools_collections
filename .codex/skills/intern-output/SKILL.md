# intern_output Skill - 产出生成器

## 背景

实习或者工作期间，经常有一些文档，这些文档的技术性强，但是内容比较多、比较散，可能不太适合用来直接作为个人项目产出写在简历上，同时不适合用作面试过程中"白话"式地回答问题。这些文档均需要进行转换处理

## 执行步骤（SOP）

1. **解析原始文档**：从用户提供的初始技术文档中提取以下要素：
   - 业务/问题背景、严重程度（如线上等级、影响范围、投诉量）
   - 核心难点 / 技术矛盾
   - 解决方案（含迭代过程：方案是怎么一步步演进的）
   - 量化收益（优化前 vs 优化后的指标对比）
   - 个人职责与角色（是否主导、独立完成、协作）
2. **检查信息完整度**：若以下关键信息缺失，**先向用户提问确认，不要凭空编造**：
   - 缺少量化指标（如耗时、数量级、提升百分比）
   - 缺少个人职责说明（主导 / 参与 / 独立）
   - 缺少方案迭代/思考过程（面试版尤其依赖此部分）
3. **生成简历版**：按下方「简历版结构模板」输出，突出量化结果与个人价值，控制篇幅、要点化。
4. **生成面试讲解版**：按下方「面试版结构模板」输出，用第一人称、白话叙述，重点讲"如何分析与解决"的思考过程，**不含代码段、图片、表格**。

## 输出结构模板

### 简历版结构模板

```
### <项目标题>
- 业务背景：<一句话说明场景 + 严重程度/影响范围>
- 个人职责：<主导/独立/参与，承担了哪些环节>
- 核心成果：
  - <量化成果1：优化前 → 优化后>
  - <量化成果2：体验/价值层面的提升>
  - <方案沉淀/可复用性>
```

### 面试版结构模板（白话、第一人称、无代码无图）

```
# <项目标题>（白话版）

<铺垫：背景 + 这个问题有多严重 + 我的角色>

我是如何排查解决问题的？
<梳理链路、定位瓶颈的思路>

## v1
<第一版方案、它解决了什么、还有什么不优雅的地方>

## v2
<针对 v1 缺陷的改进思路、新的瓶颈>

## v3
<进一步优化、最终效果、收益与认可>

## <可选：延伸思考/被追问的点>
<面试官可能追问的问题及自己的思考>
```

## 其他补充

- 参考的内容不一定有价值，主要是参考文档转换的风格.
- 转换出的面试讲解项目文档，不要包含代码段、图片这些，因为面试过程无法表达出来，面试过程只能用文字说.
